# 实际验收记录

2026 年 11 月 22 日，在 Windows 11 本机的隔离 Flow AI Engine 和 MySQL 上重新初始化并发布三类流程。两次初始化沿用同一测试项目及流程。用三个生成的账号实际办理，并核对同一上报编号的并发提交只产生一个派发实例。[复现和对接步骤](flow-engine-integration.md)

| 用例 | 结果 |
| --- | --- |
| 冷却泵轴承温度越限 | 紧急派发，值班确认、记录处置、复核后已关闭 |
| 温湿度传感器通信离线 | 常规派发，值班员填写误报原因后关闭 |
| 配电柜风机反馈异常 | 常规派发，复核退回补充处置，再次复核后升级结案 |
| 数据统计与血缘 | 源节点读回三条合成结案记录，质量校验和聚合成功，统计与实际源数据一致 |

在桌面 Edge 的 `1600 × 1080` 视口查看隔离演练台账和引擎状态实例。台账显示三条结案记录，正常关闭、误报关闭、升级结案各一条。实例画布右侧可以选择「复核恢复」记录并定位节点。[演练台账截图](images/alarm-console.png) · [实例画布截图](images/engine-instance.png)

越权办理、缺少误报原因以及无统计权限的请求均被拒绝。`npm test` 在 Windows Node.js 20 通过 5 项，覆盖输入、持久幂等、并发提交、结案回执和统计快照变动。

2026 年 11 月 21 日的远程演练另核对过同样三条路径及其桌面入口，统计回读包含五条合成结案记录，正常关闭两条、误报关闭两条、升级结案一条。[引擎项目的演示记录](https://github.com/Azurefly/flow-ai-engine#设备报警处置主演示)
